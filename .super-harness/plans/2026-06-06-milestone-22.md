# Milestone 22: Dream 升级 + 人格演化

**日期:** 2026-06-06
**Spec:** `.super-harness/specs/2026-06-06-memory-system-v3.md`
**依赖:** Milestone 21（短期记忆按日期文件 + 长期记忆按大分类 + SaveMemoryTool + Session Summary）

## 目标

完成 Dream 蒸馏的全面升级：
- 分类逻辑从三分类（core/topics/discard）改为五路径输出（user.md / knowledge.md / work.md / history.md / soul.md 成长部分）
- 新增人格演化能力：从 emotion + reflection 类短期记忆中提炼性格倾向和经验教训，写入 soul.md 成长部分
- soul.md 格式改造为固定部分 + 成长部分
- Dream 输入适配 Milestone 21 新增的 6 种 type 字段

## Tasks

### Task 1: soul.md 格式改造 — 固定部分 + 成长部分

**文件**: `memory/soul.py`, `memory/strategy.py`

改造内容：
- SoulManager 新增 `load_fixed()` 和 `load_growth()` 方法，分别读取 soul.md 的固定部分和成长部分
- soul.md 格式约定：
  ```markdown
  # Soul — 固定部分
  （用户定义的人格底线，Dream 不修改）

  # Soul — 成长部分
  ## 性格倾向
  （随经历累积变化）

  ## 经验教训
  （从 reflection 中提炼的行为准则）

  ## 情绪基线
  （最近的状态和氛围）
  ```
- `save()` 保持不变（写入整个文件）
- 新增 `save_growth(growth_content: str)` 方法：只更新成长部分，保留固定部分不变
- `load()` 返回完整内容（固定 + 成长），保持现有行为不变
- `build_system_prompt()` 中 `<soul>` 标签注入完整内容（固定 + 成长），不改变现有行为

**验收标准**:
- `load_fixed()` 正确提取固定部分内容
- `load_growth()` 正确提取成长部分内容
- `save_growth()` 只修改成长部分，固定部分不变
- 固定部分和成长部分之间有明确的分隔标记（`# Soul — 成长部分`）
- 若 soul.md 无成长部分，`save_growth()` 追加成长部分

### Task 2: DreamManager 五路径分类改造

**文件**: `memory/dream.py`

改造内容：
- `_classify_items()` prompt 改造：
  - 输入：短期记忆 items（带 type/category 字段）
  - 输出 JSON 格式改为：
    ```json
    {
      "user": ["核心用户画像信息1", ...],
      "knowledge": ["通用知识1", ...],
      "work": ["工作相关信息1", ...],
      "history": ["经历事件1", ...],
      "soul": ["性格倾向/经验教训/情绪状态1", ...],
      "discard": ["丢弃1", ...]
    }
    ```
  - Prompt 指引 LLM 根据 type 和内容语义判断归属：
    - `preference` + `fact`(category=user, 核心) → `user`
    - `fact`(通用知识) → `knowledge`
    - `fact` + `event`(工作相关) → `work`
    - `event`(非工作经历) → `history`
    - `emotion` + `reflection` → `soul`
    - 琐碎/过时/一次性 → `discard`
- `_validate_classification()` 适配新 6-key 结构
- 写入逻辑改造（`run()` 方法）：
  - `user` → `self._user_manager.save()` 追加到 user.md（沿用 `_append_to_user_md()`）
  - `knowledge` → `self._long_term.write_topic("knowledge.md", ...)`
  - `work` → `self._long_term.write_topic("work.md", ...)`
  - `history` → `self._long_term.write_topic("history.md", ...)`
  - `soul` → `self._update_soul_growth()`（新增方法，调用 SoulManager.save_growth()）
  - `discard` → 不写入，仅用于清理
- 降级处理保持：sink 不可用但有对应类别的 items 时视为写入失败

**验收标准**:
- LLM 返回 6-key JSON 能正确解析
- 各路径写入正确的文件
- 降级处理覆盖所有 sink（user_manager, long_term, soul_manager）
- items 中有 type/category 字段时 LLM 分类更准确

### Task 3: DreamManager 人格演化逻辑

**文件**: `memory/dream.py`

实现内容：
- 新增 `_update_soul_growth(soul_items: list[str])` 方法：
  - 读取当前 soul.md 成长部分（通过 SoulManager.load_growth()）
  - 将新 items 与现有成长部分合并，交给 LLM 做提炼：
    - 分析是否有性格倾向的变化趋势（不是个别事件，而是趋势）
    - 提炼经验教训（用户明确纠正或 agent 犯了可总结的错误）
    - 更新情绪基线（最近的状态和氛围）
  - LLM 输出改造后的成长部分内容
  - 调用 SoulManager.save_growth() 写入
- `_classify_items()` prompt 中明确 soul 类别的判断标准：
  - `emotion`：用户的情绪状态、对 agent 行为的反馈
  - `reflection`：agent 的自我反思、经验教训
  - 趋势性内容优先于个别事件
- 人格演化 LLM 调用单独进行（不与分类合并），保持职责清晰

**验收标准**:
- soul.md 成长部分能正确累积更新
- 固定部分不被修改
- LLM 能区分趋势 vs 个别事件
- 经验教训从 reflection 中正确提炼

## 设计决策

1. **人格演化 LLM 独立调用**：分类和演化分开调用 LLM，避免单次 prompt 过于复杂导致质量下降。分类是结构化任务，演化是创造性任务，适合分开处理。

2. **soul.md 固定/成长分隔**：使用 Markdown 标题作为分隔标记（`# Soul — 成长部分`），简单可靠，用户也可以手动编辑。

3. **Dream 阈值不变**：MIN_HOURS=24, MIN_SESSIONS=5 保持不变。人格演化不需要更频繁的触发，趋势判断需要足够多的数据积累。

4. **Dream 输入格式**：在 items_text 中加入 type/category 标签，帮助 LLM 更准确地分类，但不强制依赖（LLM 仍可根据内容语义判断）。
